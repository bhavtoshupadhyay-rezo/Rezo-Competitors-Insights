# Backend — Data API

Adds a real schema + datastore + CRUD API on top of the existing scraper layer.

## Architecture

```
React (src/)
   │
   ├── reads/writes structured data   ─────►  /api/db/*    (this doc)
   │                                            │
   │                                            ▼
   │                                       better-sqlite3
   │                                       server/data/insights.db
   │
   └── reads scraped enrichments      ─────►  /api/competitors, /api/voices, /api/news
                                                (pre-existing — unchanged)
```

The structured datastore and the scraped-enrichment snapshots are kept separate on purpose: hand-edited records (priced, validated, source-of-truth) live in SQLite; volatile public signals (GitHub stars, HN mentions, RSS news) live in JSON snapshots that get refreshed by cron.

## SQLite schema

[db/migrations.sql](db/migrations.sql) — `CREATE IF NOT EXISTS`, safe to re-run. Nested fields (`products`, `features`, `painPoints`, `analyticsMaturity`, …) are stored as JSON-encoded TEXT columns. SQLite's `json_extract` handles indexing if needed later; for the row counts here (low hundreds) JSON columns avoid 8 join tables per fetch.

Booleans round-trip via SQLite's `INTEGER 0/1` convention; `db/db.js#rowToObject` restores them.

## CRUD endpoints

All entities expose the same shape under `/api/db/<entity>` — generated by [routes/crud.js](routes/crud.js):

| Verb   | Path                  | Behaviour                                       |
|--------|-----------------------|-------------------------------------------------|
| GET    | `/api/db/<entity>`     | List all. Query: `?limit=`, `?offset=`, `?orderBy=` |
| GET    | `/api/db/<entity>/:id` | Fetch one                                       |
| POST   | `/api/db/<entity>`     | Create — 409 if PK exists. Validated against schema. |
| PUT    | `/api/db/<entity>/:id` | Upsert. URL `:id` wins over body's PK. Validated. |
| DELETE | `/api/db/<entity>/:id` | Remove                                           |

Validation failures return `400` with `{ success: false, error: 'Validation failed', details: [...Ajv errors] }`.

## Seeding

On every boot, [db/seed.js](db/seed.js)#`seedIfEmpty` checks each table — if empty, it imports the corresponding `src/data/*.js` module and `upsert`s rows. **Existing rows are never touched** so operator edits survive restarts.

Force a full re-seed from CLI (overwrites everything):

```bash
node server/db/seed.js
```

Pricing rows referencing competitors not in the DB are logged and skipped (orphan-safe).

## Deployment notes

- **Render free tier**: web service filesystem is *ephemeral*. The DB file is recreated and re-seeded from `src/data/*` on every redeploy. Edits made via the API will not survive a deploy. Fine for v1 / read-mostly use.
- **For persistent writes**: upgrade Render to a paid plan with a persistent disk (or swap `db.js`'s `better-sqlite3` for a Postgres client — same `ENTITIES` map applies). Mount disk at `server/data/` and set `INSIGHTS_DB_PATH=/mnt/data/insights.db`.

## Adding a new entity

1. Add a JSON Schema in `schemas/<name>.schema.json`
2. Add a `CREATE TABLE` in `db/migrations.sql`
3. Add the entity descriptor (columns + JSON flags) to `ENTITIES` in `db/db.js`
4. Add an optional `seed<Name>` function in `db/seed.js` and a row in `seedIfEmpty`
5. Mount in `index.js`: `app.use('/api/db/<name>', makeCrudRouter('<name>', <name>Schema))`

That's it. No new route file required for normal CRUD.
